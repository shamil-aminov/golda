# Задачи: контекст живёт в файле, а не в сессии

С 2026-11-04 (по образцу проекта SousTartar, только нужное). Длинная сессия медленнее и ошибается чаще; сессия
одноразовая, знание остаётся в файле.

## Правила
1. **Задача = файл** `docs/tasks/<имя>.md`, одна страница по шаблону ниже. Картинки задачи — в `docs/tasks/<имя>/`.
2. **Сессия — одна задача или шаг.** Начинает с файла, в конце обновляет его и коммитит вместе с кодом.
3. **Правки пачкой.** Пользователь показывает, Claude снимает скриншот и пишет пункт в «Правки»; чинит, когда список
   закрыт. Спорное — в «Вопросы», с вариантами и рекомендацией, пользователю одним сообщением.
4. **Готово** — «Статус: готово», файл — `git mv` в `docs/tasks/done/`.

## Шаблон
```markdown
# <Задача>
Статус: в работе | собираем правки | ждёт пользователя | готово · Обновлено: ГГГГ-ММ-ДД

## Цель
Одна-две фразы: что должно стать правдой.

## Решения пользователя
Дословно или близко к словам, с датой. Только это — источник направления.

## Правки
1. **Что не так.** Где, скриншот. Причина, если понятна.

## Сделано
- коммит — что

## Осталось
- [ ] шаг

## Вопросы
- вопрос — варианты — рекомендация

## Подводные камни
Что неочевидно в коде и чего не трогать.

## Готово, когда
Проверяемый критерий: кадр на dev, тест.
```

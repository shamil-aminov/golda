# Инструкции для Claude в проекте Golda

## В начале сессии
Сессия короткая: одна задача или её шаг. Войти в курс за минуту:
1. [docs/tasks/](docs/tasks/) — открытые задачи; взять свою, читать её файл целиком.
2. [docs/backlog.md](docs/backlog.md) — надиктовки, ещё не ставшие задачами.
3. По задаче: [SPEC.md](SPEC.md) (как приложение должно работать), [CONTRIBUTING.md](CONTRIBUTING.md) (сборка,
   тесты, dev-вариант), [docs/RELEASING.md](docs/RELEASING.md), [CHANGELOG.md](CHANGELOG.md) (что уже было).

## Как мы работаем
- Пользователь — дизайнер, автор видения. Надиктовывает пожелания (часто голосом); Claude делает всё: код, проверку,
  документацию, релиз. **Общение — по-русски.** Код, комментарии, коммиты и CHANGELOG — по-английски, как в репозитории.
- **Задача = файл** `docs/tasks/<имя>.md` (шаблон — [docs/tasks/README.md](docs/tasks/README.md)). Знание живёт в файле,
  а не в длинной сессии: в конце сессии обновить «Сделано / Осталось / Подводные камни» и закоммитить.
- **Правки собираются пачкой.** Пользователь показывает на телефоне, Claude снимает скриншот, пишет пункт в файл
  задачи; чинит, когда пользователь скажет, что список закрыт. Скриншоты чужих приложений и правок — хранить
  (`research/` рядом с проектом или папка задачи), не удалять. Скриншоты банков — удалять после использования.
- **Сами решаем техническое.** Всё, что меняет вид, ощущение или смысл, — вопрос пользователю, коротко, с вариантами и
  рекомендацией; спорный вид — сначала варианты кадрами.
- **Логика без додумывания за человека**, где он об этом не знает: если приложение что-то выбирает само, это должно
  быть видно (обводка, подпись) или спрошено (переключатель).

## Телефон и сборки
- **Телефон не трогать по умолчанию** (2026-11-04, пользователь: «не могу пользоваться телефоном свободно»): кадры —
  скриншот-тестами на компьютере (Roborazzi/Robolectric, `ScreenshotTest`, временные тесты для вариантов). Эмулятора
  нет и не ставить — нагрузит компьютер, там параллельно тяжёлый проект. Телефон — только когда пользователь сам
  попросит (установка релиза, снимок того, что у него на экране).
- adb: `/c/Users/sh/AppData/Local/Android/Sdk/platform-tools/adb.exe`, в Git Bash с `MSYS_NO_PATHCONV=1`.
- **Проверять на `dev`** (`sh.aminov.golda.dev`, «Golda dev», демо-данные `--ez golda.samples true`): `./gradlew
  assembleDev`. Debug-сборку не ставить. Перед установкой — `aapt2 dump packagename`.
- **Основное приложение** (`sh.aminov.golda`) — данные пользователя. Ставится только релизный APK из CI. Правки данных —
  через интерфейс приложения; через копию (Восстановить) — только для больших переносов и с согласием.
- Не водить телефон, пока им пользуется пользователь; не жать системные окна разрешений. Перед нажатиями проверять,
  какое приложение впереди (`dumpsys window | grep mCurrentFocus`): «Назад» из dev может выйти в основную Golda.

## Релиз (каждая правка — целиком, не спрашивая)
Проверки → версия в `app/build.gradle.kts` (+1 к versionCode) → раздел в CHANGELOG → коммит →
`git push origin HEAD:main` → `git tag -a vX -m X && git push origin vX` → дождаться APK
(`curl -I .../releases/download/vX/Golda-X.apk` до 302; API GitHub без ключа упирается в лимит) → проверить
`sha256sum -c`, версию и подпись (`ec61cee0…4e`) → `adb install -r`. Перед релизом с заметными изменениями вида —
показать на dev и дождаться «выпускай».
